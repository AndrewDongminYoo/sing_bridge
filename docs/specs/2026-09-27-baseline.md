# SingBridge Baseline

## Intent

Help listeners practice singing foreign-language lyrics with readable pronunciation beside the original text.
The operator approved project initialization and a basic KMP implementation after the initial research.
The operator selected the temporary product name SingBridge and folder name `sing_bridge`.

## Initial experience

Provide one original Japanese practice verse with manually authored Hangul pronunciation.
Bundle an original instrumental timing guide and label it clearly as a sample without vocals.
Allow playback, pause, progress seeking, selection of a lyric line, selected-line repeat, and hiding or revealing the lyrics.
Highlight the line using the audio player's reported position.
Pause when the app leaves the foreground.
Keep the experience offline and require no account or permissions beyond normal playback.

## Architecture

Use a `shared` Kotlin Multiplatform library for Compose UI and practice logic.
Use separate `androidApp` and `iosApp` hosts.
Use Android Media3 and iOS AVPlayer behind a small `AudioPlayer` interface.
Keep a JVM target only for fast tests of common behavior.
Do not build automatic transliteration, streaming integrations, recording, or persistent progress in this baseline.

## Constraints

Use Android API 26 or later and iOS 17.2 or later.
Use bundle ID `io.github.andrewdongminyoo.singbridge` for development.
Keep original text, pronunciation, line ID, start time, and end time together.
Reject invalid or overlapping lyric intervals.
Treat line intervals as start-inclusive and end-exclusive.
Do not replace actual playback with a simulated clock.

## Acceptance

Common tests must cover line boundaries, gaps, repeat boundaries, line selection, end-of-track replay, and hiding state.
Android debug assembly and lint must run.
The iOS simulator framework and host must build when the installed toolchain permits it.
Record actual native runtime evidence separately from compilation evidence.
Record remaining platform or audio-output checks honestly.
