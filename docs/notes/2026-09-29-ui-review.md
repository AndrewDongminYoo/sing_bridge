# UI review of the practice screens

On 2026-09-29, the Home, My Songs, and YouTube screens were reviewed on `origin/main` at `35dfa11` for visual quality, usability, accessibility, and interaction behavior.
The review read the Compose screens, the WebView page fragments, and the iOS and Android hosts, and then checked the findings on the iPhone 17 Pro simulator (iOS 27.0) with a debug build of the same commit.
The verdict was "needs changes", with eight findings.
This note records each finding, the change made for it, and what was checked after the change.

## Operator decisions

- The feature is called 음차 in user-facing text; 발음 stays only where it means the sound that the singer actually sings.
- Runtime checks use the booted simulator, not the physical device.

The contrast ratios use the relative-luminance formula of the Web Content Accessibility Guidelines 2 against `#faf7f0`, with the 0.8 opacity composited over the background.
The lyric status stays outside `lyrics-settings` because that section collapses after a lyric is chosen, and the status also carries later messages.

## Checks

Tests in `tools/test-youtube.mjs` cover findings 1, 2, 4, 6, 7, and 8.
They were written before the changes and failed with assertion mismatches; the three #39 review-label tests were updated to expect `음차 확인 필요`.

| Command                                                                                     | Result                      |
| ------------------------------------------------------------------------------------------- | --------------------------- |
| `node --test tools/test-youtube.mjs server/pronunciation.test.mjs`                          | 137 tests, 137 pass, exit 0 |
| `./gradlew :shared:jvmTest`                                                                 | exit 0                      |
| `xcodegen generate --spec iosApp/project.yml`, then the README simulator `xcodebuild` build | `BUILD SUCCEEDED`, exit 0   |

On the simulator, with a saved practice (Vaundy - odoriko, LRCLIB #35923881, offset 5.5 s, saved 음차), the fixed build showed:

- The YouTube tab has no title bar, and 영상 열기 is an outlined secondary button below the dark 노래 검색 button.
- The 가사·설정 panel lists the lyric details and status, the collapsed search, 시간 직접 입력, the 음차 section, and the save button, in that order.
- Non-current lyric rows are gray without fading the green 음차 layer.
- With the system appearance set to dark, the YouTube page, the Home screen, the status bar, and the tab bar stay light, and the selected tab is visible.
- After a relaunch at the extra-extra-extra-large text size, the YouTube page text is larger than at the default size; before the change the page was pixel-identical at both sizes.
- At the default text size the iOS page is slightly larger than before, because the iOS body text style is larger than the old `16px` root: the first discovery sentence now wraps to a second line where the baseline fit it on one. Other platforms keep `16px`.

Rows with a review flag or a Spanish segment only appear after a paid generation request, so labels 2 and 6 on those rows were checked by the tests and the computed contrast, not on screen.

## Remaining gaps

- Android WebView text zoom was not checked; the page does not read the Android font scale.
- Android was not run on an emulator for this review, so the bottom inset under the WebView was not checked.
- The lyric scroll motion was not measured.
- The status bar strip above the iOS YouTube page is the system background, not the page color.
